# CueVex 專題報告 8 分鐘講稿

## 01 封面
各位好，我的專題是 CueVex 智慧撞球訓練平台。它整合即時球位辨識、投影輔助、AI Coach 與手機端數據服務，希望把撞球練習從「打完憑感覺」改成能即時看見、能得到建議、能回放檢討，也能長期追蹤進步的訓練流程。

## 02 目錄
今天會依序說明研究背景與動機、問題定義、系統目標、系統架構、使用技術、核心功能、系統畫面展示、分析流程、實作成果、遇到問題與解決方式，最後做結論與未來展望。

## 03 研究背景與動機
撞球練習很依賴回饋，但一般玩家在練習時通常只能靠自己判斷或事後看影片。這會讓球路選擇、力道控制與母球停位很難被客觀記錄。現在 computer vision、WebSocket、LLM 與雲端資料庫已經成熟，所以我希望把這些技術整合成一套可以現場輔助、事後分析、手機追蹤的訓練平台。

## 04 問題定義
這個專題要解的不是「能不能偵測到球」這麼單一的問題，而是整個練習流程有很多資料斷點。第一，玩家缺少即時回饋。第二，練習與對戰紀錄如果沒有統一資料，就很難做長期分析。第三，桌面端需要相機、投影與 GPU，手機端需要帳號與社群服務，兩邊必須有清楚分工。

## 05 系統目標
CueVex 的目標是建立一個完整閉環。現場端要能即時辨識球位、球色、球號與穩定狀態；練習端要能透過投影顯示擺球位置、目標袋口與輔助線；AI Coach 要把盤面資訊轉成玩家聽得懂的建議；手機端則負責個人頁、社群、封鎖安全與數據能力總覽。

## 06 系統架構
整體架構分成桌面端與雲端手機端。桌面前端用 React 和 TypeScript，後端用 FastAPI，負責相機、YOLO、MJPEG、WebSocket、投影與錄影。AI Coach 是獨立的本機 WebSocket service，連接 vLLM/Gemma。Mobile 端則用 Expo，後端部署 Cloud Run mobile-lite，資料放在 Supabase。

## 07 使用技術
AI 視覺使用 YOLO、OpenCV、球色球號後處理與穩定性偵測。後端使用 Python、FastAPI、REST API、WebSocket 與 SQLite。前端使用 React、TypeScript、Vite 與 Burn-in MJPEG 串流。AI Coach 使用 vLLM/Gemma、語意摘要與對話記憶。手機端使用 Expo、React Native、Cloud Run 與 Supabase。

## 08 核心功能
核心功能分成四類。第一是現場監控，包含即時串流、球框 overlay 與系統狀態。第二是練習投影，包含球桌校正、擺球輔助與準度訓練。第三是 AI 對話，支援畫面分析、產生建議與操作導覽。第四是回放與 Mobile，包含錄影列表、事件紀錄、個人頁、社群與數據總覽。

## 09 系統畫面展示
這裡展示三個主要入口。桌面監控畫面負責即時訓練與辨識狀態；AI Coach 畫面提供自然語氣的擊球建議與問答；Mobile App 則讓使用者登入、看社群、管理個人頁並查看能力總覽。三者加起來，形成現場練習到手機追蹤的完整使用流程。

## 10 分析流程
分析流程從相機影像開始，先取得 ROI 與球桌畫面，接著用 YOLO 和校正資料得到球位、球色與球號。系統再把原始座標整理成合法目標、袋口線索、阻擋資訊與風險摘要，最後輸出到 overlay、投影輔助、AI Coach 建議與錄影回放。

## 11 實作成果
目前已完成可示範的端到端系統。桌面端有監控、YOLO、投影校正、練習與錄影回放；AI Coach 有對話記憶、畫面分析與產生建議；Mobile 有登入、社群、個人頁、封鎖安全與數據看板；工程面也有 API 文件、診斷端點、測試規範與部署腳本。

## 12 遇到問題與解決方式
實作過程中遇到幾個主要問題。畫面與 overlay 同步問題，改用後端 Burn-in MJPEG 解決。Mobile HTTP 500 很難定位，所以新增 Cloud Run 與 profile diagnostics。AI Coach 服務可能 port 漂移，因此固定 8010 並加上 health check。最後，AI Coach 在遊玩模式可能造成作弊疑慮，所以系統限制遊玩模式使用。

## 13 結論與未來展望
總結來說，CueVex 已經把即時辨識、投影練習、AI 建議、回放與手機數據整合成一個可持續迭代的平台。未來可以補齊單球擊球事件、角度誤差、力道誤差與母球落點紀錄，進一步提升數據可信度，讓 AI Coach 從輔助建議變成更個人化的訓練系統。
