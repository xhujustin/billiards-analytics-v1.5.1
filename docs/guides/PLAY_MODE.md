# 遊玩模式指南

## 06/27: '套用全袋放寬進球消失判定到遊玩模式'

### 範例

好友對戰或九號球遊玩中，若任一目標球進入袋口接近區後因鏡頭角度、桌框遮擋或洞口陰影而從 YOLO 結果消失，後端可將該球加入 `potted_balls`，再交由九號球規則判定比分、換手與犯規。

```json
{
  "mode": "nine_ball",
  "potted_balls": [3],
  "cue_ball_potted": false,
  "auto_pot_detection": true
}
```

### 規範用法

- 此規則套用六個袋口，不做單一袋口特例。
- 遊玩模式進袋消失確認使用 `2` 幀，與一般練習一致。
- 遊玩模式進袋接近區使用 `hole_radius + 160px`，目前約 `212px`。
- 若球被偵測到完全進洞，仍可直接加入 `potted_balls`。
- 若球沒有完全進洞但在進袋接近區連續消失，加入 `potted_balls`。
- 遊玩模式仍由 `apply_auto_shot_result` 套用九號球規則；此調整只影響視覺層「哪些球被視為進袋」。
- 為避免比分誤判，遊玩模式在沒有洞口座標時不使用全域消失即進袋判定。

### 輸出格式

```json
{
  "first_contact": 3,
  "potted_balls": [3],
  "cue_ball_potted": false,
  "is_foul": false
}
```

## 05/14: '新增遊玩模式選擇 UI'

### 範例

遊玩模式頁提供已接入正式流程的入口，讓使用者從主導覽快速進入遊戲流程：

```text
Dashboard -> Game -> GamePage mode=setup
```

主要卡片：

- 好友對戰

### 規範用法

- 首頁狀態維持 `currentPage='game'`，由 `GamePage` 控制內部模式。
- 好友對戰會進入完整設定流程，確認後沿用既有 `/api/game/start`。
- 未接入正式流程的任務挑戰、9 號球挑戰、限時挑戰、每日挑戰、排行榜與 mock 遊玩紀錄不顯示在遊玩模式首頁。
- 遊戲模式不再依賴 AI Coach 側欄；AI Coach 只保留在即時影像與訓練頁。

模式卡片範例：

```json
[
  {
    "標題": "好友對戰",
    "按鈕": "建立對戰"
  }
]
```

### 輸出格式

遊戲紀錄卡片可輸出：

```json
{
  "時間": "2024/06/05 20:15",
  "遊玩模式": "9 號球",
  "任務名稱": "9 球清台挑戰",
  "結果": "完成",
  "分數": "150 分",
  "耗時": "03:45"
}
```

## 06/05: '移除遊玩模式未接入功能入口'

### 範例

遊玩模式首頁只顯示目前可用的好友對戰入口：

```text
Dashboard -> Game -> GamePage mode=setup -> 好友對戰
```

### 規範用法

- `GamePage` 首頁不再渲染每日挑戰、任務挑戰、9 球挑戰、計時闖關、mock 遊玩紀錄與本週排行榜。
- `建立對戰` 直接切換到好友對戰設定流程，後續仍使用既有 `/api/game/start` 啟動遊戲。
- 若未來要恢復其他遊玩入口，需先接入實際資料來源、開始流程與回放/紀錄輸出，再新增首頁卡片。

### 輸出格式

```tsx
<button type="button" className="play-secondary-button" onClick={handleOpenFriendMatch}>
  建立對戰
</button>
```

### 驗證

- 執行 `cd frontend && npm run build`。
- 點擊頂部「遊戲」，確認遊玩模式首頁只剩「好友對戰」卡片。
- 點擊「建立對戰」，確認可進入「建立好友對戰」設定頁。

結果狀態規範：

- `完成`：任務或對戰正常完成。
- `失敗`：挑戰未達目標。
- `進行中`：尚未結束的遊戲。

## 06/20: '遊玩模式直接進入好友對戰設定'

### 範例

頂部導覽進入遊戲頁後，不再顯示「選擇遊玩模式」首頁，直接顯示好友對戰建立流程：

```text
Dashboard -> Game -> GamePage mode=legacySetup
```

### 規範用法

- `GamePage` 初始模式為 `legacySetup`，遊戲結束或返回選單時也回到好友對戰設定頁。
- 好友對戰建立頁上方不顯示「建立好友對戰」標題與說明文字，第一屏直接呈現玩家 1、玩家 2 與邀請控制。
- 玩家資訊區不再包在外層設定卡片中，只保留玩家資訊卡本身。
- 玩家資訊卡採精簡高度；玩家 2 未加入時只保留 `現場好友` 與 `掃描 QR Code`，其中 `現場好友` 顯示在左側。
- 兩張玩家資訊卡需固定同寬同高；邀請按鈕移到玩家 2 卡片下方左側對齊，使用正常操作按鈕尺寸。
- 玩家 2 加入後，原本取消操作顯示為 `移除`，固定在玩家 2 卡片右側垂直置中。
- 點擊 `掃描 QR Code` 後需以置中 modal 顯示 QR Code，背景使用虛化遮罩，右上角提供叉叉按鈕關閉；QR 產生前後不得改變玩家資訊卡尺寸。
- 設定段落取消外層卡片視覺，不顯示 `1` 到 `6` 的 numbered section 標記。
- 設定段落採左側標題、右側控制內容的列式排版；窄螢幕可退回上下排列。
- `遊戲類型`、`遊玩局數`、`出手時間限制` 使用下拉選單調整，不使用圖示、球號標記或分段按鈕。
- 未開放的遊戲類型仍保留在下拉選單中但設為 disabled，避免誤送未完成規則到 `/api/game/start`。

### 輸出格式

```tsx
<select value={roundSelection} onChange={(event) => handleRoundSelection(event.target.value as RoundSelection)}>
  <option value="3">3局</option>
  <option value="5">5局</option>
  <option value="7">7局</option>
  <option value="custom">自訂局數</option>
</select>
```

### 驗證

- 執行 `cd frontend && npm run build`。
- 點擊頂部「遊戲」，確認直接進入好友對戰設定頁。
- 確認頁面上方不再顯示建立頁標題、副標與返回遊玩模式按鈕。
- 確認遊戲類型、遊玩局數與出手時間限制皆為下拉選單。

## 05/15: '新增好友對戰建立 UI'

### 範例

遊玩模式頁點擊 `好友對戰` 卡片後，進入好友對戰設定流程。

### 設定流程

好友對戰設定分為：

- 玩家邀請
- 遊戲類型
- 對戰局數
- 出桿時間限制
- 自動判定與紀錄
- 開始前檢查
- 開始對戰

### Mock 行為

玩家 1 預設顯示目前帳號 `@123` 或登入使用者名稱。玩家 2 初始為等待加入狀態。

邀請按鈕：

```json
{
  "分享 QR Code": "讓玩家 2 模擬加入",
  "輸入好友代碼": "讓玩家 2 模擬加入"
}
```

### 遊戲設定

遊戲類型第一版只開放 `9 球`，`8 球`、`10 球` 與 `自訂規則` 顯示為 disabled。

局數選項：

```json
["3 局", "5 局", "7 局", "自訂局數"]
```

出桿時間限制：

```json
["不限時", "每桿 30 秒", "每桿 45 秒", "每桿 60 秒", "自訂"]
```

自動判定與紀錄：

```json
[
  "自動進球計分",
  "犯規偵測",
  "合法擊球提示",
  "儲存對戰紀錄"
]
```

### 輸出格式

開始對戰時應整理設定物件：

```json
{
  "players": ["玩家1", "現場好友"],
  "gameType": "nine_ball",
  "targetRounds": 5,
  "shotTimeLimit": 30,
  "options": {
    "auto_pot_detection": true,
    "foul_detection": true,
    "auto_scoring": true,
    "target_ar_hint_enabled": true,
    "saveBattleRecord": true
  }
}
```
